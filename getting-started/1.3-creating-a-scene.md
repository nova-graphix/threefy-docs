# 1.3 Creating a scene

All 3D components to be created should be child elements of the \<ThreeCanvas/> element. As you can see in the following example code,

* There are \<perspectiveCamera/> and \<scene/> elements within the \<ThreeCanvas/> element,
* There are \<directionalLight/> and \<mesh/> elements within the \<scene/> element.
* Inside the \<mesh/> element, \<boxGeometry/> and \<meshStandardMaterial/> elements exist.

The relationship between them is not necessarily that of parent and child. By using attach, a child element can become a property of the parent element. In addition, the use of attach can be omitted in the case of geometry or material because the specific relationship is clear.

```js
// main.jsx
import { createRoot } from 'react-dom/client'
import App from './App.jsx'
import './index.css'
createRoot(document.getElementById('root')).render(
    <App />
)
```

```javascript
// App.jsx
import { ThreeCanvas } from 'threefy'
const App = () => {
    return <ThreeCanvas>
        <perspectiveCamera args={[ 60, 1.23, 0.1, 1000 ]} position={[ 0, 0, 50 ]}/>
        <scene>
            <ambientLight args={[ 0xffffff, 0.5 ]}/>
            <directionalLight args={[ 0xffffff, 1 ]} position={[ 1, 2, 3 ]}/>
            <mesh>
                <boxGeometry args={[ 20, 20, 20 ]}/>
                <meshStandardMaterial color={'yellow'}/>
            </mesh>
        </scene>
    </ThreeCanvas>
}
```

## Placing and sizing the canvas

`<ThreeCanvas>` renders an element of its own and puts the canvas inside it, so you position and size it with ordinary CSS — nothing special is required.

By default it fills the box you put it in:

```jsx
<div style={{ width: 400, height: 300 }}>
    <ThreeCanvas> … </ThreeCanvas>
</div>
```

It keeps following that box: change the layout, resize the window, open a sidebar — the renderer and the camera aspect are updated for you.

To pin a size instead, give it `width` and `height` in pixels. A canvas sized this way ignores window resizing:

```jsx
<ThreeCanvas width={320} height={240}> … </ThreeCanvas>
```

| prop | meaning |
| --- | --- |
| `width` / `height` | fixed size in pixels. Omit both to follow the containing box. |
| `style` | inline style for the element `ThreeCanvas` renders |
| `className` | class name for that same element |
| `dom` | mount into an element you already own, instead of one threefy renders. `ThreeCanvas` then renders no DOM of its own and never removes your element. |

> **Note (v2.1):** earlier versions appended the canvas to `document.body`, outside the React tree, so your own CSS could not reach it. If your canvas was sized by the window and its container gives it no height, it keeps filling the window exactly as before.

## More than one canvas

You can render as many canvases as you like. **Each one owns its own scene, camera, controls, renderer and render loop** — they share nothing.

```jsx
<div style={{ display: 'flex', gap: 12, height: '70vh' }}>
    <div style={{ flex: 1 }}><ThreeCanvas><Room/></ThreeCanvas></div>
    <div style={{ flex: 1 }}><ThreeCanvas><Detail/></ThreeCanvas></div>
</div>
```

Inside a canvas, `useThree()` and the hooks always refer to **that** canvas. Unmounting one leaves the others untouched.

> **Breaking change (v2.1):** until v2.0 the renderer was a module-wide singleton, so repeating `<ThreeCanvas>` silently folded into a single canvas. That was a side effect, not a feature. If you used several tags to assemble **one** scene, drop the extra tags and use ordinary components and `<group>` instead — see [2.9 Writing your own components](../syntax-rules/2.-syntax-rules.md).

Nesting one canvas inside another is almost certainly a mistake — the inner elements go into the inner scene and appear to vanish — so threefy reports it in the console.

## Mounting and unmounting the canvas

`<ThreeCanvas>` is an ordinary React component, so you can render it conditionally:

```jsx
{ showScene && <ThreeCanvas> … </ThreeCanvas> }
```

**Unmounting it puts everything away.** The render loop stops, every DOM listener is detached, the renderer is disposed, the GPU resources threefy created are released, and the canvas element is removed from the page. Nothing keeps drawing behind your UI and nothing keeps responding to the mouse. Mounting it again starts from a clean state.

> **Note (v2.1):** earlier versions never tore the canvas down. The canvas lived outside the React tree, so it stayed visible and kept rendering after its component was gone.

React `StrictMode` mounts every component twice in development. Threefy recognises that pattern and does not tear the canvas down in between, so you are not paying to create a renderer twice.

If you hand threefy an element of your own to render into, that element is yours — threefy removes only what it added inside it:

```js
new Threefy({ dom: myDiv })
```
