# 2. Syntax Rules

## 2.1 args

The following code is a JavaScript code that creates a box geometry using its constructor provided by three.js

```javascript
const boxGeometry = new THREE.BoxGeometry( width, height, depth, widthSegments, heightSegments, depthSegments )
```

The code below is a short version of the three.js code above using threefy.

```markup
<boxGeometry args={[ width, height, depth, widthSegments, heightSegments, depthSegments ]} />
```

Note that as in the example above, all input arguments to the class constructor found in three.js can be entered to the args property of the element provided by threefy. The following table summarizes these features of threefy. The left and right code snippets below produce identical results.

| three.js                                  | threefy                    |
| ----------------------------------------- | -------------------------- |
| const mesh = new THREE.Mesh( …arguments ) | \<mesh args={arguments} /> |

## 2.2 property (eg: position, rotation, scale)

The following code defines the position, scale, and rotation of the mesh in three.js.

```js
const mesh = new THREE.Mesh(...)
mesh.position.set( px, py, pz )
mesh.scale.set( sx, sy, sz )
mesh.rotation.set( rx, ry, rz )
```

The above code can be rewritten as shown below.

```markup
<mesh position={[px,py,pz]} scale={[sx,sy,sz]} rotation={[rx,ry,rz]} />
```

In the above code, px, py, and pz represent the x, y, and z coordinates, respectively; sx, sy, and sz represent scaling factors in the x, y, and z directions, respectively; and rx, ry, and rz represent the rotation angles (in radians) in the x, y, and z directions, respectively. The comparison table below summarizes these features of threefy. The left and right sides of the table represent three.js code and threefy code, respectively, and produce the same result.

| three.js                                                         | threefy                    |
| ---------------------------------------------------------------- | -------------------------- |
| <p>const mesh = new THREE.Mesh()</p><p>mesh.property = value</p> | \<mesh property={value} /> |

## 2.3 method (as like a property)

In three.js, a 3D object with a method executes its function by inputting a value (or function) to that method and then calling the method. In threefy, an element with a method treats the method as a property, setting a value (or function) to the method property to execute the method. The following two examples illustrate these features, and the last example summarizes them.

<table><thead><tr><th width="401">three.js</th><th>threefy</th></tr></thead><tbody><tr><td><p>const material = new THREE.MeshBasicMaterial()</p><p>material.onBeforeRender = (renderer, scene, camera) => { ... }</p></td><td><p>&#x3C;meshBasicMaterial</p><p>  onBeforeRender={(renderer, scene, camera) => { ... }}</p><p>/></p></td></tr><tr><td><p>const mesh = new THREE.Mesh()</p><p>mesh.rotateY( Math.PI/4 )</p><p>mesh.translateX( 10 )</p></td><td><p>&#x3C;mesh</p><p>  rotateY={Math.PI/4}</p><p>  translateX={10}</p><p>/></p></td></tr><tr><td><p>const object = new THREE.Object3D()</p><p>object.method( value )</p></td><td>&#x3C;object3D method={value} /></td></tr></tbody></table>

In the table above, onBeforeRender() is a method of the THREE.MeshBasicMaterial object, while rotateY() and translateX() are methods of the THREE.Mesh object. For more information, see [https://threejs.org/docs/](https://threejs.org/docs/).

> **Note (v2.0 / WebGPU):** the GLSL-based `onBeforeCompile` hook is not available under the WebGPU renderer. To customize shading, use **node materials** with **TSL** (see [5.1 Core](../basic-react-elements/5.1-core.md) and [5.3 Extensions](../basic-react-elements/5.3-extensions.md)) instead of patching compiled GLSL.

## 2.4 attach

The following code shows how to use _attach_. The word, attach is a built-in keyword that does not indicate a child relationship of a parent element, but indicates that it is a property of the parent element.

```markup
<mesh scale={5}>
    <boxGeometry args={[10,10,10]} attach='geometry' />
    <meshBasicMaterial color={color} attach='material' />
</mesh>
```

In the above code, we have that mesh.geometry = boxGeometry and mesh.material = meshBasicMaterial. Note that attach can be omitted in case of attach='geometry' or attach='material' for readability of the code.

## 2.5 dash(-)

The position.x in three.js is expressed as the position-x in threefy. Similarly, scale.y and rotation.z are expressed as scale-y and rotation-z, respectively.

```javascript
mesh.position.x = 10
mesh.scale.y = 2
mesh.rotation.z = Math.PI/2
```

```markup
<mesh position-x={10} scale-y={2} rotation-z={Math.PI/2} />
```

## 2.6 color

Colors in three.js can be expressed in various ways as follows.

```javascript
<material type={'basic'} color={'red'} />
<material type={'basic'} color={0xff0000} />
<material type={'basic'} color={[1,0,0]} />
<material type={'basic'} color={new THREE.Color(1,0,0)} />
```

## 2.7 texture url

The texture of three.js can be created using the texture loader function of three.js as follows, but it can also be created by simply entering the url.

```markup
<meshBasicMaterial map={new THREE.TextureLoader().load(url)} />
<meshBasicMaterial map={url} />
```

**An empty string means "no texture".** This is convenient when the URLs come from a configuration object and some slots are unused:

```markup
const terrain = { mapURL: 'images/diffuse.jpg', bumpURL: '' }

<meshStandardMaterial map={terrain.mapURL} bumpMap={terrain.bumpURL} />   // no bump map
```

> **Note (v2.1):** an empty URL used to reach the loader, where `img.src = ''` produced a network error. Nothing is requested now.

**A texture that fails to load is not remembered.** The next render asks for it again, so a file that appears later — or a network that comes back — is picked up. To be told about the failure, load it yourself:

```js
const { threefy } = useThree()

threefy.loadTexture( url,
    ( texture ) => { … },              // loaded
    ( error, url ) => { … }            // failed (a console warning is printed either way)
)
```

## 2.8 texture sub-properties

Once a texture map is set (by URL or `THREE.Texture`), its sub-properties can be adjusted declaratively as props, without reaching for a ref. There are two forms.

**Per-map** — `<mapName>-<sub>`, where `mapName` is any texture map on the material (`map`, `normalMap`, `roughnessMap`, `aoMap`, `emissiveMap`, …):

```markup
<meshStandardMaterial
    map={url}
    map-repeat={[2,2]}          // [u,v]; a scalar (e.g. map-repeat={2}) means uniform [v,v]
    map-offset={[0.1,0]}
    map-rotation={0.5}          // radians
    map-anisotropy={16}
    map-wrap={'repeat'}         // 'repeat' | 'clamp' | 'mirror' (sets both wrapS and wrapT)
    normalMap-wrapS={'mirror'}  // wrapS / wrapT can also be set individually
    map-colorSpace={'srgb'}     // 'srgb' | 'linear' | 'none'
/>
```

**All maps** — `texture<Sub>` applies the same sub-property to every loaded texture map on the material at once:

```markup
<meshStandardMaterial
    map={colorUrl} normalMap={normalUrl} roughnessMap={roughUrl}
    textureRepeat={2}            // repeat all maps 2×2
    textureWrap={'repeat'}
    textureAnisotropy={16}
    textureColorSpace={'srgb'}
/>
```

Notes: setting `repeat` automatically switches the wrap mode to `RepeatWrapping` when it was still the default `ClampToEdge` (otherwise tiling would be invisible). Sub-props are applied after the base map has loaded, and threefy clones the texture on first sub-prop write so that other users of the same cached URL are not affected.

## 2.9 Writing your own components

You can group threefy elements into your own components and use them anywhere inside `<ThreeCanvas>`. No build configuration is needed — threefy resolves its lowercase tags at render time, including the ones your components **return**.

```markup
const Crate = ({ size = 10, ...props }) => (
    <mesh {...props}>
        <boxGeometry args={[ size, size, size ]} />
        <meshStandardMaterial map={'images/crate.gif'} />
    </mesh>
);

// use it like any other element
<ThreeCanvas>
    <Crate position={[0,0,0]} />
    <Crate position={[20,0,0]} size={5} />
</ThreeCanvas>
```

Three rules apply.

**Define components at module top level.** Do not define a component inside another component's body. Its function identity changes on every render, so React treats it as a different component and remounts it — which destroys and rebuilds the three.js objects underneath. Threefy prints a console warning when it detects this.

```markup
// ✗ redefined on every render → remounted every render
const Scene = () => {
    const Crate = () => <mesh>…</mesh>;
    return <Crate />;
}

// ✓ stable identity
const Crate = () => <mesh>…</mesh>;
const Scene = () => <Crate />;
```

**Use function components.** Class components are not supported inside the threefy tree; the lowercase tags they return are not resolved. Threefy prints a console warning.

Wrappers such as `<Context.Provider>`, `<Profiler>` and `<StrictMode>` are fine — the elements inside them are resolved as usual.

```markup
<ThreeCanvas>
    <ThemeContext.Provider value={theme}>
        <Crate />          {/* resolved normally */}
    </ThemeContext.Provider>
</ThreeCanvas>
```

> **Note (v2.1):** these used to be passed through untouched, so lowercase tags inside them never reached the scene — silently, with no error.

**Conditional rendering is fine.** Returning different element types on different renders — including early returns — works as expected:

```markup
const Loaded = ({ model }) => {
    if( !model ) return <Text>loading…</Text>;
    return <primitive object={model} />;
}
```

> **Note (v2.1):** in earlier versions this pattern could fail with React's `Rendered fewer hooks than expected` error, because threefy executed your component inside its parent's render. Components are now rendered in their own place in the React tree, so hooks, `useEffect` cleanup, error boundaries, and React DevTools all behave normally.

Your own hooks still follow React's rules — call them unconditionally, in the same order every render. `useFrame`, `useKeyDown` and `useKeyUp` are the exception: inside a threefy component they register no hooks of their own, so they may be called conditionally, more than once, or after an early return (see §3.4).

```markup
const Spinner = ({ ready }) => {
    const ref = useRef( null );
    if( ready ) useFrame( t => { ref.current.rotation.y = t } );   // fine
    return <box ref={ref} />;
}
```

If a parent needs a reference to the three.js object your component creates, forward the `ref` to your root element:

```markup
const Crate = ({ ref, ...props }) => <mesh ref={ref} {...props}>…</mesh>;
```

## 2.10 Re-rendering keeps the same object

An element creates its three.js object once. When the component re-renders, threefy **updates that object** with the new props rather than building a replacement:

```markup
const Box = () => {
    const [ color, setColor ] = useState('red');
    // every click re-renders — but it is the same THREE.Mesh throughout
    return <mesh onClick={() => setColor('blue')}>
        <boxGeometry args={[10,10,10]} />
        <meshStandardMaterial color={color} />
    </mesh>;
}
```

Two things follow, and both matter in practice:

- **`ref.current` is stable.** It keeps pointing at the same object across renders, so anything you set on it imperatively — through `useSetup`, a `useFrame` callback, or plain three.js code — survives the next render instead of being discarded with a replaced object.
- **The scene does not accumulate.** Re-rendering leaves one object where there is one element.

`args` is the exception worth knowing. It is a constructor argument, not a property, so it cannot always be applied to a live object. Threefy compares the values: unchanged `args` reuse the object, and changed `args` rebuild the geometry it belongs to. Prefer props for anything that varies — `scale` over new `boxGeometry` args, for instance.

How that comparison works is worth a moment, because it decides whether a rebuild happens on every render. Threefy compares `args` one position at a time, and only one level deep:

| What you pass                                                                | Compared by                             |
| ---------------------------------------------------------------------------- | ----------------------------------------- |
| numbers, strings, booleans                                                   | value                                   |
| `THREE.Vector2`, `Vector3`, `Color` and the other three.js math objects      | `equals()`, so by value                 |
| an array of numbers, such as a `polyhedronGeometry` vertex list              | its length and each element             |
| a plain options object, such as `{ depth: 2, bevelEnabled: false }`          | its keys and their values               |
| anything else — a `THREE.Shape`, a `Curve`, an `Object3D`, your own class    | identity                                |

The last row is the one that catches people. A `Shape` or a `Curve` built in the component body is a **new object on every render**, so the geometry that takes it is rebuilt on every render — quietly, because the result looks identical:

```jsx
const Heart = () => {
    const shape = new THREE.Shape();   // new object every render -> geometry rebuilt every render
    shape.moveTo( 0, 0 );
    // ...
    return <mesh><shapeGeometry args={[ shape ]}/><meshBasicMaterial/></mesh>;
}
```

Hoist it to module scope, or wrap it in `useMemo`, and the geometry is built once:

```jsx
const Heart = () => {
    const shape = useMemo( () => {
        const s = new THREE.Shape();
        s.moveTo( 0, 0 );
        // ...
        return s;
    }, [] );

    return <mesh><shapeGeometry args={[ shape ]}/><meshBasicMaterial/></mesh>;
}
```

Threefy cannot do this for you: two `Shape` objects holding the same curves are still two objects, and comparing them deeply would cost more than rebuilding the geometry.

The same rule now covers post-processing passes and effects. Changing their `args` builds a new one and takes the old one out of the pipeline:

```markup
<unrealBloomPass args={[ undefined, strength, 0, 0 ]} />   // change strength → applied
```

> **Note (v2.1):** passes and effects used to be created once and never rebuilt, so a changed `args` had no effect at all. Replacing one also used to leave the old pass in the pipeline, where it kept rendering.

> **Note (v2.1):** earlier versions rebuilt an element's three.js object on every render and left the previous one in the scene. If you wrote code that worked around that — re-applying imperative setup after each render, or clearing stale objects yourself — it is no longer needed.

## 2.11 Conversion helpers

Props and `args` accept plain numbers and arrays in most places, and threefy turns them into the three.js objects underneath. The same conversions are exported as functions, for the times you need one in your own code — building `args` for a curve, reading a colour out of a config file, or turning a flat coordinate array into points.

```js
import { toColor, toVector3, toVector2s, toVector3s, toVector4s } from 'threefy'
```

`toColor( color )` returns a `THREE.Color`. A `Color` is passed through unchanged, and `null` or `undefined` gives `undefined` rather than throwing.

```js
toColor( 0xff0000 )        // from a hex number
toColor( 'red' )           // from a CSS colour name or string
toColor( [ 1, 0, 0 ] )     // from [ r, g, b ]
```

`toVector3( point )` returns a `THREE.Vector3`. A single number — or a numeric string — fills all three components, which is handy for uniform scales.

```js
toVector3( [ 1, 2, 3 ] )       // Vector3( 1, 2, 3 )
toVector3( { x: 1, y: 2, z: 3 } )
toVector3( 2 )                 // Vector3( 2, 2, 2 )
```

`toVector2s( points )`, `toVector3s( points )` and `toVector4s( points )` return an **array** of vectors, and each accepts four shapes of input. This is what lets curve and surface elements take a flat list of numbers:

```js
toVector3s( [ [ 0,0,0 ], [ 1,1,1 ] ] )      // array of arrays
toVector3s( [ 0,0,0, 1,1,1 ] )              // one flat list, read three at a time
toVector3s( [ { x:0, y:0, z:0 } ] )         // array of objects
toVector3s( [ new THREE.Vector3() ] )       // already vectors — accepted as well
```

`toVector2s` reads two numbers at a time and `toVector4s` reads four. All three return an empty array for `null` or `undefined`.

Note that these three always hand back a **new array of new vectors**, including when you pass vectors in. Keep your own reference if you intend to mutate the originals later.

> **Note (v2.0):** these were named `THREE_Color`, `THREE_Vector3` and `THREE_Vector2s` / `THREE_Vector3s` / `THREE_Vector4s` in 1.x. They were renamed to verb form because they convert rather than construct; the old names are gone.
